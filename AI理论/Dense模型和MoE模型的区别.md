# Dense 模型与 MoE 模型的区别

## 一句话总结

- [[Dense 模型]]：每次前向计算几乎“全模型上阵”，参数被用到的比例高，但计算开销随参数量线性上升。
- [[MoE（Mixture of Experts）]]：把部分层拆成多个“专家”，每次只路由激活少数专家，做到“参数很大、但每次计算较省”。

> [!note] 直观类比
> Dense 像“全员开会一起做题”；MoE 像“分科专家值班，来题就叫对应专家上场”。

## Dense（稠密模型）

### 核心机制

- 传统 Transformer 架构（如 GPT-3 一类的 Dense LLM）。
- 输入任意 token 时：每一层的主要计算路径都会被执行，层内的大多数参数都会参与计算。

### 计算方式

- 每层、每个子模块（注意力 + FFN 等）都会对输入进行变换。
- 计算成本通常与模型参数量同阶增长（更严格地说：与每次前向实际参与的参数/算子规模强相关）。

### 关键特点

- 参数量 ≈ 计算量：例如 175B 的 Dense 模型，处理每个 token 时基本都需要“搬动”这一规模的参数参与前向计算。
- 工程实现相对直接：训练/推理路径固定，调度简单，稳定性较好。

## MoE（专家混合模型）

### 核心机制

- 主流演进方向之一（如一些 MoE 系列、Mixtral 等）。
- 将模型中的某些层（通常是 FFN/全连接相关层）替换为“多专家并列”的结构：同一位置上有多个小模块（专家）。

### 门控网络（Router）

- 核心部件：为每个 token（或 token group）计算路由分数。
- 常见策略：Top-1 / Top-2 路由（每次选 1 个或 2 个专家参与计算）。

### 计算方式

- 每次只激活少数专家，因此每个 token 的实际计算量显著低于“把所有专家都跑一遍”。
- 典型描述：参数总量可以很大（例如 1.8T），但每次只动其中一小部分（例如 50B 量级的激活参数）。

> [!warning] MoE 的“省”主要省在计算，不一定省显存
> 推理时仍需加载/容纳大量参数（取决于部署方式与并行策略），因此 MoE 的优势更多体现在“每 token FLOPs 更低”，而不是“参数不占空间”。

## 对比表（最重要）

| 维度 | Dense（稠密模型） | MoE（专家混合模型） |
| --- | --- | --- |
| 参与计算的参数 | 每次几乎全模型参与 | 每次只激活少数专家（稀疏激活） |
| 参数量与计算量关系 | 参数量 ≈ 计算量（同阶增长） | 参数量可以很大，但计算量按激活专家规模计算 |
| 训练/推理复杂度 | 路径固定，工程较简单 | 路由与负载均衡带来额外复杂度 |
| 扩展性（参数扩展） | 扩参通常直接增加计算 | 更容易“扩参不等比例增算” |
| 典型适用 | 追求稳定、简单、通用性强 | 追求更高参数容量与较低每 token 计算 |

## 你可以记住的 3 个关键词

- Dense：全量激活、路径固定、计算随参数量上升
- MoE：稀疏激活、路由选择、参数大但每 token 计算可控
- Router：决定“该叫谁来算”的核心组件
